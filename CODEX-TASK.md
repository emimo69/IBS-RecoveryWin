# CODEX-TASK.md — Prossima fase: IP desktop, Monta ISO, WinRE e avvio OS in QEMU

**Leggi AGENTS.md ed ESEGUI questo incarico quando l'utente scrive «Leggi CODEX-TASK.md».** Operare solo nel ramo ibs-recoverywin-1.0 e progetto /opt/ibs-recoverywin-1.0. Conservare integralmente ISO R2 e base admin/admin, SSH, TeamViewer, /mnt/teamviewer.txt, launcher, lingua italiana. Nessuna cancellazione, sovrascrittura ISO, modifica progetti precedenti o dischi fisici.

## Fase A — subito, implementare e testare
1. Verifica sorgenti GitHub e rapporto docs/TEST-1.0-R2-RESULTS.md; correggi solo problemi accertati. Aggiungi un indicatore chiaro dell'indirizzo IP locale **nell'angolo alto destro del desktop XFCE**, aggiornato dinamicamente (considera ethernet/wifi, nessun IP e cambio DHCP), leggibile senza aprire terminale. Se Conky è già usato per TeamViewer, non interrompere quel servizio o sovrascrivere le sue funzioni.
2. Aggiungi icona sul desktop **Monta ISO**: scelta origine NAS QNAP (//192.168.20.123/Public/ISO tramite mount guest senza password, senza credenziali hard-coded) oppure partizione dati chiavetta USB Ventoy. Rileva Ventoy correttamente, anche se già montata, e restituisci percorsi puliti senza sequenze letterali \\n. Montaggi GUI devono dare feedback chiaro e non alterare supporti USB in scrittura. Assicurati che selettore file veda ISO e rispetti spazi nei percorsi.
3. Dal pulsante Monta ISO poter avviare ISO di recupero con QEMU in **UEFI OVMF o Legacy**: tra quelle supportate, IBS-WinRE.iso (CPU host con KVM, come verificato in 0.1), Acronis, altre ISO. Non dare per scontato che WinRE funzioni senza KVM; chiara diagnostica quando il server/guest non espone KVM. Per il nuovo progetto, il test QEMU host senza KVM NON prova WinRE annidato.
4. Aggiungi modalità separata **Avvia sistema operativo da disco**: avvio del Windows installato su disco intero selezionato, distinto dall'avvio ISO. Di default accesso **protetto** (snapshot/overlay QCOW2 con disco base realmente non scrivibile); scelta esplicita e avviso per qualsiasi accesso diretto in scrittura, solo dopo validazione dei dischi e dei mount. Proteggere sistematicamente Ventoy, disco Live e dischi montati. Non alterare il disco reale durante questi test.
5. Esegui test statici/mock della selezione disco, escaping percorsi, boot UEFI/Legacy, args QEMU e opzioni readonly; prepara test con file immagine QCOW2 fittizi. NON avviare dischi fisici.

## Fase B — salvataggi e collaudo
6. Commit + push GitHub dopo IP, dopo selezione ISO, dopo QEMU e dopo preparazione test; conferma che hash remoto=locale. In ogni fase testa regressioni di SSH, TeamViewer, launcher e file TXT.
7. Se il setup è pronto, ricompila una nuova ISO R3 in percorso isolato, senza cancellare né sovrascrivere R2 o cache e senza clean --purge. Avvia **solo la Live R3 senza dischi** in QEMU/TCG sul server, verificando boot/SSH/TeamViewer e presenza launcher Monta ISO + IP (quanto realmente verificabile). Documenta test veri e limiti della GUI. Non montare NAS o USB reali sulla Debian di sviluppo solo per la prova. NON collegare QCOW2 Windows da 64GB al test R3.
8. Per test effettivi di WinRE e avvio Windows da disco, indica che servirà un host con KVM e un disco virtuale contenente un OS; NON affermare successo fino a prova reale. Se una correzione non è verificabile senza hardware, segnalala come non verificata senza ulteriori modifiche casuali.

**PRIORITÀ: nessuna regressione delle funzioni già funzionanti. Non inviare credenziali TeamViewer su GitHub. Non modificare timer o utenti del server. Nessun accesso in scrittura ai dischi fisici durante questo incarico.**
